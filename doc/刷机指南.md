# FPV 固件刷机指南

适用固件:
- `target/CoreELEC-Amlogic-ng.arm-21.2-Omega_devel_<时间戳>-Generic.img.gz`(通用镜像)
- `target/CoreELEC-Amlogic-ng.arm-21.2-Omega_devel_<时间戳>-ZTE_W100D.img.gz`(中兴 W100D 专用)

目标设备:Amlogic-ng arm 设备(S905X2 等 FPV 板)

## 板型说明

| 板型 | SoC | 内存/存储 | 内置 DTB | 说明 |
| --- | --- | --- | --- | --- |
| Generic | 多型号 | - | 由 `device_trees/` 自行选择 | 通用镜像,首次启动需选 DTB |
| ZTE_W100D | S905X2 (G12A) | 2G DDR4 / 8G eMMC | `g12a_s905x2_2g.dtb` | 中兴 uSmart 云电脑 W100D(太极云电脑),保留原厂 u-boot,镜像自带 `dtb.img`,无需手动选 DTB |

W100D 若网口为千兆版本,可把 `projects/Amlogic-ce/devices/Amlogic-ng/bootloader/dtb.conf`
中该条目换成 `g12a_s905x2_2g_1gbit.dtb` 后重新构建。

> 增量构建时若内核包未重编,`ZTE_W100D_dtb.img` 可能不会生成(镜像内缺 `dtb.img`)。
> 遇到这种情况删除 `build.CoreELEC-Amlogic-ng.arm-21/.stamps/linux/build_target` 后重新构建,
> 或直接做一次干净构建。

> 刷机前请确认时间戳为**最近一次成功构建**的产物。早期批次(如 QA 失败中断前的版本)
> 缺少 GStreamer 插件,请勿使用。

## 准备工作

```bash
cd target
# 校验镜像完整性
sha256sum -c CoreELEC-Amlogic-ng.arm-21.2-Omega_devel_<时间戳>-Generic.img.gz.sha256
# 解压
gunzip -k CoreELEC-Amlogic-ng.arm-21.2-Omega_devel_<时间戳>-Generic.img.gz
```

## 方式 A:SD 卡启动(最安全,推荐先用)

1. 准备一张 8GB+ 的 MicroSD 卡,插入 PC(假设为 `/dev/sdX`,**务必确认盘符,写错会毁数据**):

```bash
sudo dd if=CoreELEC-Amlogic-ng.arm-21.2-Omega_devel_<时间戳>-Generic.img \
     of=/dev/sdX bs=4M conv=fsync status=progress
sync
```

2. SD 卡插入设备,上电开机。
   - 部分盒子需**按住 AV 孔内复位键(牙签法)再上电**,强制从 SD 启动。
3. 首次启动约 1-2 分钟,看到 OSD 界面即成功。
4. (可选)从 SD 迁入 eMMC —— SSH 登录后执行:

```bash
ceemmc -x
```

> ⚠️ `ceemmc -x` 会**清空 eMMC 全部数据**,完成后断电、拔卡、重新上电即从 eMMC 启动。

## 方式 B:USB 烧录(maskrom,直刷 eMMC)

需要 Windows PC + Amlogic USB Burning Tool(v2.x / v3.x):

1. 用工具"导入"解压出的 `.img`(不要导入 .gz)。
2. 设备**断电**,用 USB A-A / A-C 线连接盒子 **OTG 口**(通常是中间那个 USB 口)到 PC。
3. 按住复位键(或短接主板 CLK 测试点)后上电,工具右下角显示 **Connect** 后松手。
4. 勾选 `擦除 flash` → `ERASE FLASH` 选项(首次或换系统时建议勾选),点击 **Start**。
5. 进度 100% 显示 **Burn successfully** 后断电拔线,正常上电启动。

## 方式 C:旧 CoreELEC 系统内升级(不推荐)

将 `target/*.tar` 上传到设备 `/storage/update/` 后重启,系统自动升级。

> ⚠️ 本次 FPV 版本新增了 GStreamer 组件与服务,增量升级可能遗留旧依赖问题,
> 正式部署请使用方式 A 或 B 全量刷写。

## eMMC 已装 Armbian 时从 U 盘/SD 卡启动

W100D 使用原厂 u-boot,Armbian 安装到 eMMC 后会执行 `saveenv`,把 u-boot 环境
改成它自己的启动链:

```
bootcmd = run start_autoscript; run storeboot
start_autoscript = SD 找 s905_autoscript → USB 找 s905_autoscript → eMMC 找 emmc_autoscript
```

也就是说它**只认 `s905_autoscript`,不认 CoreELEC 的 `aml_autoscript`**,
所以插着 CoreELEC U 盘时会被跳过,继续从 eMMC 启动 Armbian。

更麻烦的是,该环境里 USB 扫描写作 `if usb start; then ...`,而这颗原厂 u-boot
(U-Boot 2015.01)只有 `usb start 0` 才能成功,导致 **USB 扫描整段被静默跳过**。
W100D 镜像自 2026-10-24 起已内置 `s905_autoscript` 和 `cfgload`;若 eMMC 环境里
的 `start_usb_autoscript` 不可靠,可用 `target/usb-boot-fix/emmc_autoscript.usbtry`
替换盒内 `/boot/emmc_autoscript`,由它在 eMMC 启动链里强制扫描 SD→USB:

```bash
# 盒子(Armbian)上
sudo cp /boot/emmc_autoscript /boot/emmc_autoscript.orig
sudo cp /tmp/emmc_autoscript.usbtry /boot/emmc_autoscript
sync
```

旧镜像可只补这两个文件(位于 `target/usb-boot-fix/`):

```bash
# U 盘第一分区(COREELEC,FAT32)挂载后
cp target/usb-boot-fix/s905_autoscript /media/$USER/COREELEC/
cp target/usb-boot-fix/cfgload         /media/$USER/COREELEC/
sync
```

插 U 盘上电:u-boot 先扫描 USB,发现 `s905_autoscript` 后启动 CoreELEC;
拔掉 U 盘则继续从 eMMC 启动 Armbian(脚本不改写 u-boot 环境,两者可共存)。

> 若仍不启动,接串口(`ttyAML0`,115200)确认 u-boot 是否扫描到 USB。
> 在 u-boot 命令行手动启动:
>
> ```
> usb start
> fatload usb 0:1 ${loadaddr} cfgload
> setenv device usb; setenv devnr 0; setenv partnr 1; setenv ce_on_emmc no
> run storeargs
> autoscr ${loadaddr}
> ```

## W100D 已知问题:HDMI 显示异常

部分接在 W100D 上的显示器不能正确显示 YUV444 信号,现象是**画面只显示在屏幕上半部、
水平方向重复 3 个相同的模糊画面**。

- 镜像自 2026-10-29 起内置 `ZTE_W100D_cfgload`,默认以 `rgb,8bit` 输出,可避免该问题
- 同时内置 Kodi 出厂默认 `coreelec.amlogic.forcecs=1`(强制 RGB):
  仅 cfgload 传 RGB 还不够 —— Kodi 切显示模式时会把 `/sys/class/amhdmitx/amhdmitx0/attr`
  重置回 YUV444,导致 logo 正常、进 Kodi 后花屏。设置该项后 Kodi 按 EDID 协商时
  始终输出 RGB
- 注意:该默认值只在 `/storage` 首次创建(全新刷机)时生效。旧 storage 升级时可在
  Kodi **设置 → 播放器 → 视频 → Force colour subsampling** 选 RGB,或重新选择一次
  分辨率(如 1080p60)让 Kodi 重新协商

## 刷机后验证

SSH 登录设备(`root`,默认密码 `coreelec`):

```bash
# FPV 服务应均为 active (running)
systemctl status amlgsmenu amldigitalfpv

# GStreamer 视频链插件应在位
gst-inspect-1.0 udpsrc
gst-inspect-1.0 rtph265depay
gst-inspect-1.0 h265parse
gst-inspect-1.0 appsink

# 首次启动后 OSD 资源应已 bootstrap 到 /storage
ls /storage/digitalfpv/{icons,fonts,wfb.conf,command.cfg}
```

排查:

```bash
journalctl -u amldigitalfpv -u amlgsmenu --no-pager -n 50
```

## 注意事项

- `gs.key`(wfb-ng 链路加密密钥)为**每台部署单独生成**,不会打包进通用镜像;
  需自行放置到 `/storage/digitalfpv/` 并在 wfb.conf 中启用。
- SD 卡长期使用建议 `dd` 时保持 `conv=fsync`,避免缓存写入中断损坏分区。
- 镜像含中文 OSD 字体(约 46MB),SYSTEM 分区为 squashfs 只读,**不要**试图手工挂载修改。
